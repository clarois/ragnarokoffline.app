# Settings: Save data

Your characters and accounts, and the folder everything lives in.

There are two kinds of backup. **Back up database** keeps your characters and
accounts. **Back up everything** keeps those too, plus your settings and
installed mods. Each has a matching restore.

## Back up database

Writes one `.sql` file with every account, character, item, guild and storage
of **both** eras, renewal and pre-renewal. Your settings and installed mods are
not in it; use Back up everything for those.

Players are briefly disconnected so their latest state is saved consistently.
That is a few seconds, not a stop.

Worth doing before an app update, before enabling internet hosting, and before
any experiment you would mind losing.

## Restore database

Opens a `.sql` backup and shows what it holds — which version made it and when,
and how many accounts and characters each era has — with a checkbox for each
era. What you leave unticked stays as it is. The era you have now is saved
first, and you are shown where, so a restore is itself undoable. The game stays
stopped until you restart the server.

A `.sql` backup from 1.4.3 or before holds one era and does not say which. It
restores into the era you have set in Settings → General → **Game era**, so set
that first.

## Back up everything

Writes one `.tar.gz` with both eras' characters and accounts, **your settings
and your installed mods**: everything you need to keep a world or move it to
another computer. Sharing and Cloudflare credentials and your game client's
files are never in it; your accounts' passwords are, so keep it private.

## Restore everything

Opens a `.tar.gz` backup and shows what it holds, with a checkbox for each part:

- **Renewal characters & accounts**
- **Pre-renewal characters & accounts**
- **Settings & installed mods**

What you leave unticked stays as it is. Everything as it is now is saved first,
and you are shown where. The server restarts with the restored world.

## When a restore fails

The message says what the database objected to, and every step is kept in
`state/logs/restore-<time>.log` in the app's data folder. Settings → Tools →
**Log viewer** shows every backup and restore under *Backup & restore*, and
Settings → **Report a problem** includes the last restore.

Backups record which version of the app made them, the era and the client
version, and a backup from an older version is brought up to date as it is
restored.

An untested backup is not a backup. Restoring one into a throwaway install once
is worth the five minutes.

## Open data folder

Opens the folder holding everything the app generates: the microVM, its disks,
the server runtime and your settings. Useful for attaching a log to a bug
report, or copying a backup somewhere safe by hand.

| Platform | Location |
|---|---|
| macOS | `~/Library/Application Support/Ragnarok Offline` |
| Windows | `%APPDATA%\Ragnarok Offline` (that is `AppData\Roaming`, not `Local`) |
| Linux | `~/.local/share/Ragnarok Offline` (or `$XDG_DATA_HOME/Ragnarok Offline`) |

Inside it:

| Entry | What it is |
|---|---|
| `nebula/` | The microVM: guest kernel, container images, and the virtual disks. Nearly all of the size. |
| `runtime/` | The server runtime — rAthena config, SQL schema, the client. Replaced wholesale by each app update. |
| `state/` | Generated config, seeded schema, and staged backups. Deliberately outside `runtime/` so an update cannot wipe it. |
| `state/mods` | Installed mods. Outside the asset tree on purpose, so rebuilding assets cannot destroy them. |
| `state/crashes` | Preserved map-server crashes, including the symbolised stack a bug report wants. |
| `client.json` | Which folder your GRFs are in, and whether you are hosting or joining. |

**Your Ragnarok client is not in here.** The GRFs stay wherever you put them and
are read in place, so a 3.5 GB client is never duplicated — and nothing on this
page can put it at risk.

## Copying diagnostics

Not on this page — it is in the app's own menu — but this is the place to
mention it. **Copy diagnostics** collects the app version, your settings, the
server logs, any preserved crash reports and the sharing log into one block of
text you can paste into a bug report.

It never includes passwords or invitation tokens.
